# Map Stage 4 Implementation Plan: placement

**Goal:** Where the picture sits inside each shape:
- Fit with zoom, move and turn
- Pin, in true perspective
- Across group and Across stage
- shapes sharing one instrument, or made separate
- brightness and tint per shape
- four stage corners that fix a nudged projector

**Done when:** a grid pinned to an angled box face looks square to the eye, and nudging the projector is fixed with four handles.

**Architecture:** See "Stage 4 decisions" in the design.
- The perspective maths is pure and tested with `node:test`: `src/map/homography.ts` and `src/map/placement.ts`.
- The wall's compositor moves to WebGL2 (Greg's choice, after Task 1's measurements; see "Stage 4 decisions").
  - Each shape is one quad with cached pictures: coverage, border and its own fill. Instruments are uploaded as textures.
  - Overlays are drawn in 2D when they change.
  - The stage-corner pass comes last.
- The show moves to version 4.

**Spec:** [docs/projection-mapping-design-2026-11-16.md](../../projection-mapping-design-2026-11-16.md): Build order stage 4 row, "Placement: how the picture sits in the shape", "Look, edge and timing" (Look), "Stage 4 decisions".

**Branch:** `map-stage-4`, from `main` at be92fa3. It is built in the `three VJ - main` folder, so the project folder and Codex's unsaved work there stay untouched.

**Execution:** native (the controller implements). Independent reviews:
- after Task 3 (maths, format and edits)
- after Task 6 (wall drawing)
- a whole-branch review at the end

## Global Constraints

- Studio's loops, seeking and export must not change. Studio and Live tests pass untouched.
- No edit may blank the output.
  - A change of placement is a small change: it takes effect at once, with no fade.
  - A pin that would fold the picture over itself is refused: red on the operator screen, and the last good one stays on the wall.
- No mapping jargon on screen. The words are Fit, Pin, Across group, Across stage, Zoom, Move, Turn, Share with, Make separate, Brightness, Tint, Stage corners. Never "homography", "UV", "input" or "output", apart from the agreed Open output and Close output.
- Version 1 to 3 shows open with the same meaning. The largest valid show still fits `MAP_MESSAGE_LIMIT`, which is tested.
- The operator screen shows the stage flat, and the projector's preview is captured before the stage-corner warp.
- Performance: `scripts/measure-map.mjs` keeps the stage 3 figures. A new `--pin` run puts all eight shapes on Pin, with stage corners set. Measured on a quiet Mac, the target is 120 fps with no frame over 16.7 ms.

## Review Focus

1. **A pin quad that is not convex**, or nearly flat: refused, with the reason said, before the maths turns it inside out. Tests: Tasks 1 and 3.
2. **Stage corners that cross**: refused. Reset always works, even on a locked show or with every shape locked. Test: Task 3.
3. **A shared instrument when a shape leaves:**
   - deleting one sharer keeps the source for the others
   - Make separate on the last sharer changes nothing
   - undo restores the sharing

   Test: Task 3.
4. **Across group when the group changes.** Members leave, the group is dissolved, or it is hidden: the picture re-covers the new box, and a member without a group falls back to Across stage. Tests: Tasks 2 and 6.
5. **The warp helper's graphics context is lost:** pinned shapes fall back to Fit, the stage corners fall back to flat, the operator is told, and the helper is restarted after a pause, as for instruments. Test: Task 6.
6. **The wall preview with stage corners set:** the operator's outlines still line up with the picture. Test: Task 9.

### Task 1: Measure the warp helper (spike, kept only if it holds)

**Files:** `scripts/map-spike/warp-cost.mjs` (throwaway); results are written into the design under "Stage 4 decisions".

On this Mac, at a 1920 × 1080 stage, with the output open:

- Then `drawImage` the result into the 2D stage.

### Task 2: Perspective maths and placement

**Files:** Create `src/map/homography.ts` and `src/map/placement.ts`. Tests: `tests/map-homography.test.ts` and `tests/map-placement.test.ts`.

**Interfaces:**
```ts
export type H3 = [number, number, number, number, number, number, number, number, number];
export function squareToQuad(q: Point[]): H3 | null;               // null when the quad is not convex or nearly flat
export function quadToQuad(from: Point[], to: Point[]): H3 | null;
export function invert(h: H3): H3 | null;
export function apply(h: H3, p: Point): Point;
export function isPinnable(q: Point[]): { ok: true } | { ok: false; reason: 'pin-folded' | 'pin-flat' };
/** Where a shape's picture lands: a box with zoom, move and turn (Fit and Across), or a perspective quad (Pin). Stage pixels. */
export type Landing = { kind: 'box'; box: Box; matrix: Matrix } | { kind: 'quad'; quad: Point[]; h: H3 };
export function landing(shape: Shape, show: { shapes: Shape[]; groups: Group[] }): Landing;
export function sourceSizeFor(landings: Landing[], scale: number): { width: number; height: number };   // replaces playout's per-shape box rule
export function pinGridLines(quad: Point[], divisions: number): PatternLine[];   // true-perspective grid for the pattern
```

**Tests:**
- The four corners map exactly, and the centre maps to where the diagonals meet.
- `invert` followed by `apply` is the identity.
- A bow-tie, a concave quad and a flat quad are refused.
- Fit with zoom 2 doubles the box about its centre; Move shifts it; Turn 90° swaps its width and height in pixels.
- Across stage lands on the full stage; Across group lands on the group's members' box. A shape with no group falls back to the stage.
- `sourceSizeFor` of a shared source is the largest landing, kept within 64 to 1920 × 1080.
- Perspective grid lines get closer together towards the far side of a trapezoid.

### Task 3: Show version 4 and edits

**Files:** Modify `src/map/show.ts`, `src/map/editor.ts` and `src/map/messages.ts`. Tests: `tests/map-show.test.ts`, `tests/map-editor4.test.ts` and `tests/map-messages.test.ts`.

**Interfaces:**
```ts
export interface Placement { kind: 'fit' | 'pin' | 'across-group' | 'across-stage'; zoom: number; offset: Point; turn: number; pin: Point[] | null }
export interface Shape { /* v3 */ placement: Placement; brightness: number; tint: string }
export interface ShowDocument { version: 4; /* … */ stageCorners: Point[] | null }
// actions
| { type: 'setPlacement'; shapeId: string; placement: Partial<Placement> }
| { type: 'movePin'; shapeId: string; index: number; to: Point }        // only for shapes using their own pin
| { type: 'shareSource'; shapeId: string; withShapeId: string }
| { type: 'makeSeparate'; shapeId: string; sourceId: string }
| { type: 'setLook'; shapeId: string; brightness?: number; tint?: string }
| { type: 'setStageCorners'; corners: Point[] | null }
| { type: 'moveStageCorner'; index: number; to: Point }
```

- **Validation:** zoom 0.25 to 4; turn −180 to 180; offset ±1; brightness 0 to 2; tint `#rrggbb`. A pin must be four points, convex, and not flat; otherwise it is dropped back to null. Stage corners must be four convex points, otherwise null.
- **Version 1 to 3 files** take the defaults without being marked repaired.
- **Choosing Pin** on a shape without exactly four points sets `pin` to its box's corners. Moving the shape's points moves its own pin, since pin is null and follows the outline. A stored `pin` moves with `moveShapes` and `transformShapes`.
- **Sharing:**
  - `shareSource` drops this shape's own source if nothing else plays it. It is refused for Blockers, and refused when the other shape plays no instrument.
  - `makeSeparate` copies the source with a new id; for a sole player, nothing happens.
- **The wire format** carries placement, look and stage corners, rounded like the points.

**Tests:**
- One test per action and per validation rule, covering Review Focus 1 to 3.
- The largest valid version 4 show fits in one message.

### Task 4: GPU compositor, core

*Replaces the warp helper, after Task 1.*

**Files:** Create `src/map/gpu.ts` (WebGL2 programs, buffers and textures) and `src/map/stage-matrix.ts` (pure). Rewrite `src/map/compositor.ts` behind the same public interface (`setShow`, `setOptions`, `setFrozen`, `invalidate`, `frame`, `stats`, `dispose`). Test: `tests/map-stage-matrix.test.ts`.

- **Pure parts:**
  - the 3 × 3 transform from stage pixels to a shape's picture coordinates, for each landing
  - the matrices that turn stage pixels into clip space
  - the stage-corner inverse
- **Each frame:**
  1. Clear the stage framebuffer to black.
  2. For each shown shape, back to front, draw one quad over its box. The fragment shader reads its content (instrument texture, colour, or own-fill picture; two of them during a crossfade), applies brightness and tint, multiplies by coverage, and lays the border picture over.
  3. Draw the overlay picture.
  4. Run the final pass to the canvas through the stage corners.
- **Blackout** clears to black and skips everything.

### Task 5: GPU compositor, shape pictures

**Files:** `src/map/compositor.ts`, and `src/map/coverage.ts` for the 2D builders, moved from the stage 3 compositor.

- Coverage pictures are made at the box's size in projector pixels, from the outline and holes, worn and blurred for the soft edge as in stage 3. They are made again only when the geometry or the soft edge changes (`edgeBuilds` counts it).
- Border pictures and own-fill pictures (colour, or the grid pattern: corner-following for Fit, a flat grid seen through the perspective for Pin) are made only when they change.
- **Instruments:**
  - Uploaded with `texImage2D` from their canvas on frames they render.
  - The texture holds the last picture, so Freeze and half-rate drawing need no copy.
  - A crossfade copies the old texture once.
  - Shared instruments render once, at `sourceSizeFor` all their landings.
- **Unchanged behaviour:** the governor, the 24-instrument limit, prepare and failure handling, and lost instrument contexts.
- **A lost compositor context:** the wall goes black until it is restored. Every picture is then rebuilt, and `stats()` says so.

### Task 6: Stage corners and the operator's picture

**Files:** `src/map/compositor.ts`, `src/ui/MapOutput.tsx`, `src/map/preview-worker.ts`, `src/ui/MapPanel.tsx`.

- **The operator's picture of the projector:** at most five times a second, after a frame that drew, the flat stage is drawn small (480 × 270) into its own framebuffer and read into a pixel buffer behind a fence. It is collected on a later frame, never waited for. The worker encodes it as before.
- **The operator screen with the output closed:** the compositor draws into a hidden canvas, and the 2D operator canvas copies it, then draws its marks.

### Task 7: Operator screen

**Files:** Modify `src/ui/MapDetails.tsx`, `src/ui/MapPanel.tsx`, `src/map/gestures.ts` and `src/ui/useMap.ts`. Test: `tests/map-gestures.test.ts`.

**Details panel, a new "Placement" section:**
- A choice of Fit, Pin, Across group or Across stage.
- For Fit: Zoom, Move X, Move Y and Turn sliders, each committing once, and **Reset picture**.
- For Pin on a shape without four corners: the note "Drag the four pin handles on the stage", and **Reset pin**.

**Content section:**
- **Share with…**: a list of the shapes that play an instrument.
- **Make separate**, when the shape shares.
- A line saying how many shapes share the instrument.

**Look section:** Brightness slider and Tint swatches (white, warm, cool, plus a custom hex).

**Stage:**
- While a non-four-corner shape is pinned and selected, its four pin handles are drawn as diamonds and can be dragged. `pick` gains `{ kind: 'pin'; index }`, after points and before the box.
- A folded pin is refused in red.

**Header:**
- A **Stage corners** switch. While on, the shape tools are paused, the four stage-corner handles are drawn on the operator screen at the stage's corners, and dragging or arrow-nudging one moves it.
- **Reset** returns the corners to the stage's corners.

**Right-click menu:** Placement (Fit, Pin, Across group, Across stage), Share with…, Make separate.
