# Map Stage 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Map section where Greg draws rectangle and four-corner shapes over the projector's picture, saves them in a show file that autosaves, and lines them up on real objects with blackout, test grid, identify and a wall crosshair.

**Architecture:** Pure logic (show document, outline geometry, editing with history, output messages, stage drawing) lives in `src/map/` and is tested with `node:test`. Electron code lives in `electron/map.cjs` and the shared output-window helper, mirroring Live. The operator screen (`MapPanel.tsx`) and the output page (`MapOutput.tsx`) are React, mounted the way Live is. Stage 1 draws with Canvas 2D; the GPU compositor comes in stage 2.

**Tech Stack:** TypeScript (React 19, Vite), Electron 45, `node:test` via `tsx`, Playwright for scripted checks (as `scripts/verify-live.mjs`).

**Spec:** [docs/projection-mapping-design-2026-11-16.md](../../projection-mapping-design-2026-11-16.md), sections "Build order" (stage 1), "Drawing shapes", "Lining up on the real object", "How it is built", "Checks".

## Global Constraints

- Shape positions are stored as fractions of the stage, 0 to 1, origin top-left. Exact boxes show projector pixels.
- Limits: 64 shapes; 32 points a shape. Stage 1 creates only four-point shapes; the format allows up to 32 so stage 3 adds no format change.
- Stage size is fixed at 1920 × 1080 in stage 1. Follow-the-display and the other sizes come later.
- No mapping jargon on screen: no "slice", "surface", "UV", "homography", "input", "output" in labels. Use Shape, Stage, Test grid, Identify, Blackout.
- No edit may blank the output. Output updates only when a complete valid show arrives.
- Studio's loops, seeking and export must not change. Existing tests pass untouched: `npm test` before and after each task.
- Only Map and Live may open the artwork window, and never both: opening one closes the other.
- Messages between windows are capped at 16 KB (`MESSAGE_LIMIT` in `electron/live.cjs`).

## Review Focus

1. **Outline crosses itself** (a corner dragged past a neighbour): refused with a red outline on the laptop; the last valid outline stays on the wall. Test: Task 2 and Task 3.
2. **Collapsed shape** (all points on one line or one point): refused. Test: Task 2.
3. **Damaged or newer show file**: loads whatever is valid, field by field; a file that is not an object starts an empty show and is kept as `*.damaged` beside it. Test: Task 1 and Task 7.
4. **Projector unplugged while Map output is open**: output closes, the laptop is told, nothing crashes; a second display works afterwards. Test: Task 8.
5. **Arrow keys while typing in an exact-position box**: the shape must not move. Test: Task 10c.

  export function isValidOutline(points: Point[]): { ok: true } | { ok: false; reason: 'crossing' | 'collapsed' | 'too-few' | 'too-many' | 'outside' };

- [ ] **Step 1: Write the failing tests**:
  - A square `[(0,0),(1,0),(1,1),(0,1)]` is valid.
  - A bowtie `[(0,0),(1,1),(1,0),(0,1)]` → `{ok:false, reason:'crossing'}`.
  - Three collinear points `[(0,0),(.5,.5),(1,1)]` → `'collapsed'` (area under the threshold `.002`).

  - `nudge({x:0.5,y:0.5}, 1, -1)` changes `x` by `1/1920` and `y` by `1/1080` (screen y is down, so −1 px means up on the stage; the test documents this).

- [ ] **Step 3: Implement** `src/map/geometry.ts`. `isValidOutline` checks counts, then calls `isSimplePolygon`; if that returns false, reason is `'crossing'` when any two non-adjacent edges meet, else `'collapsed'`. Stage 1 accepts exactly 4 points for shapes it creates; the function accepts 3 to 32 (the format limit).
